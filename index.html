03 / GET SET UP

From template to
something useful.

A downloaded SKILL.md is an instruction file, not an app. Put it in the right folder, then ask Copilot CLI to use it. Follow the walkthrough below or watch the demo and try it later.

01

Get Copilot CLI ready

You need a GitHub account, an active Copilot subscription, and permission to use the CLI. This walkthrough is for GitHub Copilot CLI on your computer, not just the GitHub website or Outlook. Follow GitHub’s installation instructions.

Open Terminal on a Mac or PowerShell on Windows. To start Copilot, enter:

copilot

If prompted, enter /login inside Copilot and follow the sign-in instructions. Verified eligible teachers may qualify for GitHub Education benefits; staff eligibility and approval are not guaranteed.

02

Download and inspect one skill

Choose Project handoff or Weekly update above. Find the downloaded file in your Downloads folder, and open it in a text editor to review its instructions. It must be named exactly SKILL.md—not SKILL.md.txt or SKILL (1).md.

Both downloads have the same filename. Install them one at a time and put each in its own folder; if your browser adds a number, rename the file after checking which skill it contains. Avoid replacing a file you haven’t reviewed.

↗

Or ask Copilot to install it

After downloading, you can paste this prompt into Copilot CLI instead of moving the file yourself. Review the file and proposed destination, and approve only if they are correct. Copilot may ask permission to access your Downloads and skills folders.

Find the most recently downloaded workshop SKILL.md file in my Downloads folder. Read its name field to determine which skill it is, then show me the intended destination under ~/.copilot/skills/ and ask for confirmation.

After I confirm, create the matching skill folder and move the file into it as SKILL.md. Do not overwrite an existing file. Tell me how to reload the skill and verify that Copilot can see it.

Then continue to step 04 to check the skill. If you prefer to move the file yourself, follow step 03 instead.

03

Put the file in its skill folder

The folder name tells Copilot which skill this is. For example, the project handoff must be here:

~/.copilot/skills/
  project-handoff/
    SKILL.md

For the other skill, use weekly-update instead of project-handoff. To create the project folder, run one of these commands in your computer’s terminal, outside Copilot:

Mac · Terminal

mkdir -p ~/.copilot/skills/project-handoff

Windows · PowerShell

New-Item -ItemType Directory -Force -Path "$HOME\.copilot\skills\project-handoff"

For the weekly update, replace project-handoff with weekly-update in the command. Then move the downloaded SKILL.md into the corresponding folder:

  1. Mac: In Finder, choose Go → Go to Folder, enter ~/.copilot/skills/, and open your skill folder.
  2. Windows: In File Explorer, enter %USERPROFILE%\.copilot\skills in the address bar and open your skill folder.
  3. Move the file from Downloads into that folder. Confirm the file is directly inside it, not in an extra nested folder.
04

Check that Copilot can see it

Start copilot in your terminal. If Copilot was already open when you added the file, enter this inside Copilot:

/skills reload

Then enter the command for your chosen skill:

/skills info project-handoff

For the other template, use /skills info weekly-update. Check the displayed name and location. You can also enter /skills list to see available skills.

05

Ask Copilot to use it

Inside Copilot, enter one of the prompts below, including the skill name with a slash, and provide notes you’re permitted to use. Copilot reads the skill’s instructions when it is invoked, then responds to your request. Review the output; the skill doesn’t send or share it for you.

My skill isn’t showing up. What should I check?

Check that the folder name matches the chosen skill and that SKILL.md is directly inside it, with the exact spelling and extension. Run /skills reload, then /skills info project-handoff or /skills info weekly-update again. If it is disabled, open /skills and enable it. If needed, restart Copilot and consult GitHub’s CLI skill guide.

BEFORE YOU START

Keep information safe.

Confirm that GitHub Copilot and the information you intend to use are approved under FHSU policy. Don’t enter confidential, student, personnel, or other sensitive information unless explicitly permitted.

Provide a few notes yourself. The skills do not connect to Outlook or automatically read your work files. They can organize what you supply, but may miss context or make mistakes.

Not sure what’s allowed? Check with FHSU before using real work information. Never paste passwords or access tokens into a prompt.

05 / GIVE IT A TRY

Your turn to
make it useful.

After checking the skill in Copilot CLI, copy its prompt into the Copilot conversation. Replace the brackets with notes approved for your AI tool, then review the result. No Outlook connection is needed.

01

Project handoff

YOUR STARTER PROMPT

Use the /project-handoff skill to organize these approved notes for [colleague or team]: [project purpose, completed work, remaining tasks, and known deadlines]. Flag missing details and do not invent facts. Do not send or change anything.

Check the result: Confirm the status, owners, deadlines, and any information the next person needs.

02

Weekly update

YOUR STARTER PROMPT

Use the /weekly-update skill to draft an update for [audience] from these approved notes: [accomplishments, upcoming work, and any blockers]. Keep it concise, flag missing details, and do not invent facts. Do not send or change anything.

Check the result: Make sure it accurately reflects your work and is appropriate for the intended audience.

✳

You’re always in charge. Check the original notes. AI may miss context or be wrong. Review every draft before sharing it through your normal workflow.
